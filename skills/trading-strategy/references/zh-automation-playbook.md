# 自动化策略执行规范

自动化策略的目标不是让 agent 更激进，而是让规则更一致。任何无人值守策略都必须有明确的执行边界、暂停条件和错误处理方式。

## 上线前检查

- 策略规则已经写成明确条件，而不是主观判断。
- 已确认交易所、币种、合约类型和交易模式。
- 已完成模拟盘或小资金验证。
- 已定义最大单笔亏损、单日亏损和最大回撤。
- 已定义连续失败后的暂停规则。
- 已确认 API 权限只包含必要范围。
- 已确认下单数量、最小精度、合约面值和手续费。

## 自动执行输入

自动策略每次运行前应获得或计算：

```text
当前价格：
关键支撑阻力：
趋势或震荡状态：
账户权益：
当前持仓：
可用保证金：
未实现盈亏：
当日已实现盈亏：
信号是否触发：
止损位置：
目标位置：
本次允许风险：
```

## 暂停条件

触发以下条件时，不继续自动下单：

- 单日亏损达到上限。
- 策略达到最大回撤。
- 连续亏损达到阈值。
- 行情状态与策略不匹配。
- 交易所接口异常、行情数据延迟或账户数据读取失败。
- 当前仓位已经超过策略允许上限。
- 价格距离强平价过近。
- 用户要求暂停或切换到只观察模式。

## 订单执行规则

- 下单前再次确认仓位方向、数量、价格和模式。
- 市价单需要说明滑点风险；大额订单优先拆单或限价。
- 止损单应尽量与开仓配套设计。
- 不因为一次下单失败而无限重试。
- 不在 API 返回不确定状态时重复提交同一订单；先查询订单状态。

## 自动运行总结

每次策略运行结束，都应输出：

```text
运行时间：
读取的数据：
信号状态：
是否执行：
执行动作：
仓位变化：
风险变化：
暂停原因（如有）：
下一次检查条件：
```
